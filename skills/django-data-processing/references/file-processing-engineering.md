# File Processing Engineering: CSV, Excel, JSON, JSONL, XML, Plain Text

> **Scope:** How to parse text and spreadsheet formats (CSV, XLS/XLSX, JSON, JSONL, XML, plain
> text/fixed-width) safely and with bounded memory: file structure, encoding contracts,
> header/schema detection, streaming extraction, format-level vs row-level errors, and library
> choice. **Not here:** Parquet/Avro/ORC/ZIP/PDF → [columnar-archive-and-document-files.md](columnar-archive-and-document-files.md);
> field validation and `RejectedRecord` → [data-validation-and-cleansing.md](data-validation-and-cleansing.md);
> mapping/type conversion → [data-transformation-and-mapping.md](data-transformation-and-mapping.md);
> upload/preview/column-mapping UX → [data-import-and-export-systems.md](data-import-and-export-systems.md);
> deep file security (XXE, bombs, formula injection) → [data-processing-security.md](data-processing-security.md);
> chunking/parallelism → [large-dataset-processing.md](large-dataset-processing.md).

## 1. Purpose and scope

A parser's only job is to turn bytes into a stream of `(locator, raw_record)` pairs plus a
clear verdict on whether the *file* is usable. It should not validate business rules, convert
money, or touch the database. Keeping that boundary gives you:

- one parser per format, reusable by imports, ingestion, and ETL pipelines;
- precise error locators (`line 4812`, `Sheet1!row 77`, `/Invoices/Invoice[3]`) for reports;
- bounded memory: parsers are generators, so a 5 GB CSV costs the same RAM as a 5 KB one.

Covered formats: CSV/TSV, Excel `.xlsx` (OOXML) and legacy `.xls` (BIFF), JSON documents,
JSON Lines (JSONL/NDJSON), XML, plain text logs and fixed-width records.

## 2. Core concepts

| Concept | Meaning |
|---|---|
| Encoding contract | The documented byte→text encoding you accept (e.g. "UTF-8, BOM optional"). Guessing is a fallback, not a contract. |
| Locator | Stable pointer to the source of a record: physical line, sheet+row, JSON pointer, XPath-like path. Stored on every error and every rejected record. |
| Format error | The file as a whole is unreadable: wrong encoding, not a ZIP, malformed JSON document, missing required header. **Fatal** for the file. |
| Row error | One record is bad (wrong column count, unparsable cell). **Isolated**; the policy in [data-validation-and-cleansing.md](data-validation-and-cleansing.md#4-engineering-decisions-and-trade-offs) decides whether the dataset survives. |
| Header/schema detection | Locating the header row, normalising names, mapping to canonical fields, detecting missing/unknown/duplicate columns. |
| Streaming parse | Reading incrementally (line, row, element, array item) so memory is O(record), not O(file). |
| Raw record | `dict[str, str | None]` (text formats) or `dict[str, Any]` (Excel/JSON typed values) **before** type conversion. |

Physical vs logical lines: a quoted CSV field may contain newlines, so "record 10" can start
on physical line 14. `csv.reader.line_num` [stdlib] reports physical lines consumed — use it,
not `enumerate`, when users need to find the row in a text editor.

## 3. Internal mechanics

### 3.1 CSV
RFC 4180 is a loose standard: delimiter, quote char, escaping (`""` doubling vs backslash),
line endings and header presence all vary by producer. `csv.reader` [stdlib] is a state machine
over *text*; it must receive a file opened with `newline=""` so embedded `\r\n` inside quoted
fields survives. `csv.field_size_limit()` (default 131072 chars) raises `csv.Error` on a giant
field — a useful guard against "one 2 GB field" files; raise or lower it deliberately.
`csv.Sniffer` [stdlib] guesses dialect from a sample and is heuristic — use it for preview UIs,
never as the production contract.

Excel-produced CSVs: "CSV UTF-8" adds a BOM (`EF BB BF`); plain "CSV" is the Windows ANSI code
page (cp1252 in Western locales) and uses `;` as delimiter in locales where `,` is the decimal
separator.

### 3.2 Excel
- **XLSX** is a ZIP of XML parts (`xl/workbook.xml`, `xl/worksheets/sheet1.xml`,
  `xl/sharedStrings.xml`). Cells reference a shared-strings table; dates are numbers plus a
  number format. `openpyxl` [third-party: openpyxl] `read_only=True` streams sheet XML instead of
  building the full object model; `data_only=True` returns the *cached* formula result (None if
  Excel never calculated the file — e.g. files generated by libraries).
- **XLS** is binary BIFF8 in an OLE2 container. `xlrd` [third-party: xlrd] ≥ 2.0 reads only
  `.xls`; dates require `xlrd.xldate_as_datetime(value, book.datemode)`.
- Read-only worksheets trust the `dimension` tag, which some generators write wrongly
  (`A1:A1`); call `ws.reset_dimensions()` if `max_row` looks absurd.
- Merged cells, hidden sheets, multiple header rows and trailing formatted-but-empty rows are
  common; the parser must skip blank rows and pick the sheet explicitly (name, not index, when
  the contract allows).

### 3.3 JSON and JSONL
`json.load` [stdlib] parses the whole document into memory (roughly 5–10x file size in Python
objects). Use `parse_float=Decimal` [stdlib] for monetary values so `0.1` never becomes binary
float. JSONL is one JSON value per line: trivially streamable, each line independently
recoverable, and the line number is the locator. For a huge single JSON array, an incremental
parser such as `ijson` [third-party: ijson] yields items without materialising the array.

### 3.4 XML
Tree parsers (`ElementTree.parse`, `lxml.etree.parse`) build the whole tree. `iterparse`
emits `(event, element)` as closing tags are seen, **but still keeps the tree it has built**
unless you clear processed elements and delete earlier siblings. XML also carries entity and
DTD machinery (XXE, billion laughs) — parsers must have entity resolution and network access off.

### 3.5 Plain text / fixed width
Log lines and mainframe-style fixed-width records are parsed by slicing (`line[0:10]`) from a
layout spec, or by a compiled regex. Encoding (often cp1252, EBCDIC `cp037` for mainframes) and
trailing-whitespace semantics must be in the contract.

## 4. Engineering decisions and trade-offs

### 4.1 Which library when

| Situation | Prefer | Avoid / escalate when |
|---|---|---|
| Row-wise business import (CSV ≤ millions of rows) | `csv.DictReader` [stdlib] | You need vectorised analytics → pandas/Polars |
| CSV for analytical/bulk transforms | pandas `read_csv(chunksize=, dtype=str)` or Polars `scan_csv` | Per-row business validation with rich errors (DataFrames lose row context easily) |
| Very large CSV → Parquet/columnar | Polars `scan_csv(...).sink_parquet()` or `pyarrow.csv.open_csv` | Dialect is irregular — fix with stdlib first |
| XLSX import | `openpyxl` `read_only=True, data_only=True` | > ~1M cells per sheet and speed matters → `python-calamine` [third-party: python-calamine] (VERIFY: maturity/API for your version) |
| XLS legacy | `xlrd` ≥ 2.0 | Can ask users for `.xlsx` → avoid the dependency |
| JSON document ≤ tens of MB | `json.load(parse_float=Decimal)` | File can be GBs → `ijson`, or ask the producer for JSONL |
| JSONL / NDJSON | Line loop + `json.loads` | — |
| XML from untrusted source | `defusedxml` [third-party: defusedxml] or hardened `lxml.etree.iterparse` | Need XSD validation → lxml `XMLSchema` with a hardened parser |
| Fixed width / logs | slicing / `re` [stdlib] | Producer can send CSV instead |

### 4.2 Encoding strategy

| Situation | Prefer | Avoid / escalate when |
|---|---|---|
| You control the template | Contract "UTF-8, BOM optional"; decode with `utf-8-sig` | Never silently fall back |
| Users export from desktop Excel | Accept `utf-8-sig`, then cp1252 as declared fallback, record which was used | Mojibake (`Ã©`) appears → reject, ask for "CSV UTF-8" |
| Unknown partner feeds | `charset-normalizer` [third-party: charset-normalizer] on a sample, then confirm with the partner and pin it | Detection confidence low → fail the file |
| Strict financial feeds | Decode with `errors="strict"`; fail on first bad byte | `errors="replace"` silently corrupts names/amounts |

### 4.3 Format errors vs row errors

| Error | Classification | Action |
|---|---|---|
| Undecodable bytes, not a ZIP (xlsx), malformed JSON doc, XML not well-formed | Format, permanent | Fail file; no rows processed |
| Missing required column, duplicate header | Structural, permanent | Fail file before row 1 |
| Wrong field count on one CSV row, bad JSONL line | Row, permanent | Isolate; count toward error budget |
| Storage read timeout | Transient | Retry the job (see [processing-reliability-and-recovery.md](processing-reliability-and-recovery.md)) |

Note on XML: well-formedness errors after 10,000 good records mean the file is truncated or
corrupt. Decide per contract whether records already yielded are kept — default is to fail the
file, because you cannot prove the producer's intended record count.

## 5. Django/Python implementation patterns

### 5.1 Format detection and parser registry

```python
# parsing/registry.py
from __future__ import annotations
import enum
from collections.abc import Callable, Iterator
from pathlib import Path
from typing import Any, BinaryIO

type Locator = str
type RawRecord = dict[str, Any]
type Parser = Callable[[BinaryIO, "ParseOptions"], Iterator[tuple[Locator, RawRecord]]]

class FileFormat(enum.StrEnum):          # [stdlib] enum.StrEnum (Python >= 3.11)
    CSV = "csv"; XLSX = "xlsx"; XLS = "xls"; JSON = "json"; JSONL = "jsonl"; XML = "xml"; TEXT = "txt"

class FileFormatError(Exception):
    """Whole file unusable. Permanent. Carries a stable code for reports."""
    def __init__(self, code: str, message: str) -> None:
        super().__init__(message); self.code = code

class RowError(Exception):
    def __init__(self, locator: Locator, code: str, message: str) -> None:
        super().__init__(message); self.locator, self.code = locator, code

_MAGIC: list[tuple[bytes, FileFormat]] = [
    (b"PK\x03\x04", FileFormat.XLSX),                         # any OOXML/ZIP; confirm later
    (b"\xd0\xcf\x11\xe0\xa1\xb1\x1a\xe1", FileFormat.XLS),    # OLE2 compound file
]

def detect_format(head: bytes, filename: str, declared: FileFormat | None) -> FileFormat:
    for magic, fmt in _MAGIC:
        if head.startswith(magic):
            return fmt                                        # bytes beat extension
    stripped = head.lstrip(b"\xef\xbb\xbf \t\r\n")
    if stripped.startswith(b"<"):
        return FileFormat.XML
    if stripped.startswith((b"{", b"[")):
        ext = Path(filename).suffix.lower()
        return FileFormat.JSONL if ext in {".jsonl", ".ndjson"} else FileFormat.JSON
    if b"\x00" in head:
        raise FileFormatError("binary_content", "File looks binary, not text.")
    return declared or FileFormat.CSV

PARSERS: dict[FileFormat, Parser] = {}

def register(fmt: FileFormat) -> Callable[[Parser], Parser]:
    def deco(fn: Parser) -> Parser:
        PARSERS[fmt] = fn; return fn
    return deco

def parse(fh: BinaryIO, filename: str, opts: "ParseOptions") -> Iterator[tuple[Locator, RawRecord]]:
    head = fh.read(4096); fh.seek(0)
    fmt = detect_format(head, filename, opts.declared_format)
    if opts.allowed_formats and fmt not in opts.allowed_formats:
        raise FileFormatError("format_not_allowed", f"{fmt} not accepted for this import")
    yield from PARSERS[fmt](fh, opts)
```

Magic bytes beat extensions and client MIME types (both attacker-controlled); the full
type-sniffing policy lives in [data-processing-security.md](data-processing-security.md).
Storage streams from django-storages must be seekable for `seek(0)` — S3 streams are, but
verify for custom backends (VERIFY: seekability of your storage backend's file object).

### 5.2 Options and header normalisation

```python
from dataclasses import dataclass, field
import re, unicodedata

@dataclass(frozen=True, slots=True)
class ParseOptions:
    declared_format: FileFormat | None = None
    allowed_formats: frozenset[FileFormat] = frozenset()
    encoding: str = "utf-8-sig"                 # the contract
    fallback_encodings: tuple[str, ...] = ()    # e.g. ("cp1252",) only if contract says so
    delimiter: str = ","
    sheet_name: str | None = None
    header_aliases: dict[str, str] = field(default_factory=dict)  # "e-mail" -> "email"
    required: frozenset[str] = frozenset()
    xml_record_tag: str = "Record"
    max_records: int = 5_000_000

def normalise_header(raw: object, aliases: dict[str, str]) -> str:
    text = unicodedata.normalize("NFKC", str(raw or "")).strip().lower()   # [stdlib]
    text = re.sub(r"[^\w]+", "_", text).strip("_")
    return aliases.get(text, text)

def check_header(header: list[str], opts: ParseOptions) -> None:
    dupes = {h for h in header if h and header.count(h) > 1}
    if dupes:
        raise FileFormatError("duplicate_columns", f"Duplicate columns: {sorted(dupes)}")
    missing = opts.required - set(header)
    if missing:
        raise FileFormatError("missing_columns", f"Missing columns: {sorted(missing)}")
```

Header detection when the template has a title block: scan the first N rows for the row that
contains the most required column names (after normalisation) and treat it as the header;
record the chosen row in job metadata so the preview UI can show it.

### 5.3 CSV with an explicit encoding contract

```python
import csv, io

@register(FileFormat.CSV)
def parse_csv(fh: BinaryIO, opts: ParseOptions) -> Iterator[tuple[Locator, RawRecord]]:
    encoding = _choose_encoding(fh, opts)
    text = io.TextIOWrapper(fh, encoding=encoding, errors="strict", newline="")
    reader = csv.reader(text, delimiter=opts.delimiter, strict=True)
    try:
        header = [normalise_header(h, opts.header_aliases) for h in next(reader)]
    except StopIteration:
        raise FileFormatError("empty_file", "File has no header row.") from None
    check_header(header, opts)
    try:
        for count, row in enumerate(reader, start=1):
            locator = f"line {reader.line_num}"           # physical line, survives quoted newlines
            if count > opts.max_records:
                raise FileFormatError("too_many_records", f"More than {opts.max_records} records")
            if not any(cell.strip() for cell in row):
                continue                                   # blank line
            if len(row) != len(header):
                yield locator, {"__error__": RowError(locator, "field_count",
                                 f"expected {len(header)} fields, got {len(row)}")}
                continue
            yield locator, dict(zip(header, row))
    except UnicodeDecodeError as exc:
        raise FileFormatError("encoding", f"Not valid {encoding} near byte {exc.start}") from exc
    except csv.Error as exc:                              # unterminated quote, field too large
        raise FileFormatError("csv_syntax", f"{exc} at line {reader.line_num}") from exc
    finally:
        text.detach()                                      # don't close the caller's handle

def _choose_encoding(fh: BinaryIO, opts: ParseOptions) -> str:
    sample = fh.read(256 * 1024); fh.seek(0)
    for enc in (opts.encoding, *opts.fallback_encodings):
        try:
            sample.decode(enc)                             # sample may cut a multibyte char:
            return enc                                     # strict decode of full file still guards
        except UnicodeDecodeError:
            continue
    raise FileFormatError("encoding", f"File is not {opts.encoding}; save as CSV UTF-8.")
```

Note: cp1252 decodes almost any byte sequence (only 5 bytes are undefined), so it must be the
*last* fallback and its use should be recorded and surfaced. Yielding a sentinel for row
errors (instead of raising) keeps the generator alive; an alternative is a separate
`ParsedRow | RowError` union type.

Unknown encodings — detection as a diagnostic, not a contract:

```python
from charset_normalizer import from_bytes   # [third-party: charset-normalizer]

def guess_encoding(sample: bytes) -> str | None:
    best = from_bytes(sample).best()          # (VERIFY: API name/return type for your version)
    return best.encoding if best is not None else None
```

### 5.4 XLSX (openpyxl, read-only) and XLS (xlrd)

```python
from openpyxl import load_workbook          # [third-party: openpyxl]

@register(FileFormat.XLSX)
def parse_xlsx(fh: BinaryIO, opts: ParseOptions) -> Iterator[tuple[Locator, RawRecord]]:
    try:
        wb = load_workbook(fh, read_only=True, data_only=True)
    except Exception as exc:                  # zipfile.BadZipFile, KeyError for missing parts
        raise FileFormatError("xlsx_invalid", "Not a readable .xlsx workbook.") from exc
    try:
        if opts.sheet_name and opts.sheet_name not in wb.sheetnames:
            raise FileFormatError("sheet_missing", f"Sheet {opts.sheet_name!r} not found")
        ws = wb[opts.sheet_name] if opts.sheet_name else wb.worksheets[0]
        rows = ws.iter_rows(values_only=True)
        header = [normalise_header(h, opts.header_aliases) for h in next(rows, ())]
        check_header(header, opts)
        for row_no, values in enumerate(rows, start=2):
            if values is None or all(v is None or str(v).strip() == "" for v in values):
                continue
            yield f"{ws.title}!row {row_no}", dict(zip(header, values))
    finally:
        wb.close()                            # read-only mode keeps the archive open
```

Values arrive typed: `datetime`, `int`, `float`, `bool`, `str`, `None`. Floats for money must be
converted via `Decimal(str(v))` and quantised in the mapping step
([data-transformation-and-mapping.md](data-transformation-and-mapping.md)); leading zeros in IDs
(`00123`) are already lost if the cell was numeric — require text-formatted columns in the
template. pandas `read_excel(dtype=str)` has no chunking: it loads the whole sheet.

For `.xls`: `xlrd.open_workbook(file_contents=data, on_demand=True)` then `sheet.row_values(i)`;
xlrd needs the whole file in memory (bytes), so cap `.xls` size tightly
(VERIFY: on_demand memory behaviour for your xlrd version).

### 5.5 JSON, streaming JSON, JSONL

```python
import json
from decimal import Decimal

@register(FileFormat.JSONL)
def parse_jsonl(fh: BinaryIO, opts: ParseOptions) -> Iterator[tuple[Locator, RawRecord]]:
    for line_no, raw in enumerate(fh, start=1):          # binary lines; bounded by producer
        if len(raw) > 1_000_000:
            yield f"line {line_no}", {"__error__": RowError(f"line {line_no}", "line_too_long", "")}
            continue
        if not raw.strip():
            continue
        try:
            obj = json.loads(raw.decode("utf-8-sig" if line_no == 1 else "utf-8"),
                             parse_float=Decimal)
        except (UnicodeDecodeError, json.JSONDecodeError) as exc:
            yield f"line {line_no}", {"__error__": RowError(f"line {line_no}", "json_syntax", str(exc))}
            continue
        if not isinstance(obj, dict):
            yield f"line {line_no}", {"__error__": RowError(f"line {line_no}", "not_object", "")}
            continue
        yield f"line {line_no}", obj

@register(FileFormat.JSON)
def parse_json_array(fh: BinaryIO, opts: ParseOptions) -> Iterator[tuple[Locator, RawRecord]]:
    import ijson                                          # [third-party: ijson]
    # "item" = each element of the top-level array; "data.item" for {"data": [...]}
    # ijson yields Decimal for non-integer numbers by default (VERIFY: for your ijson version/backend)
    try:
        for idx, obj in enumerate(ijson.items(fh, "item")):
            yield f"/{idx}", obj                           # JSON-pointer-style locator
    except ijson.JSONError as exc:                         # (VERIFY: exception class name)
        raise FileFormatError("json_syntax", str(exc)) from exc
```

A malformed JSON *document* is a format error — the parser cannot resynchronise. A malformed
JSONL *line* is a row error. That asymmetry is the main reason to ask producers for JSONL.
Without ijson, cap the size (e.g. 50 MB) and use `json.load(fh, parse_float=Decimal)`.

### 5.6 XML: hardened `iterparse` with element clearing

```python
from lxml import etree                                    # [third-party: lxml]

@register(FileFormat.XML)
def parse_xml(fh: BinaryIO, opts: ParseOptions) -> Iterator[tuple[Locator, RawRecord]]:
    context = etree.iterparse(
        fh, events=("end",), tag=opts.xml_record_tag,
        resolve_entities=False, no_network=True, load_dtd=False,
        huge_tree=False,                                  # never True for untrusted input
    )
    try:
        for idx, (_event, elem) in enumerate(context, start=1):
            record = {child.tag: (child.text or "").strip() for child in elem}
            record.update({f"@{k}": v for k, v in elem.attrib.items()})
            yield f"{opts.xml_record_tag}[{idx}] (line {elem.sourceline})", record
            elem.clear(keep_tail=False)
            while elem.getprevious() is not None:         # drop already-processed siblings
                del elem.getparent()[0]
    except etree.XMLSyntaxError as exc:
        raise FileFormatError("xml_syntax", f"{exc.msg} at line {exc.lineno}") from exc
```

Namespaced documents need the Clark-notation tag: `tag="{urn:example:invoice}Invoice"`; strip
namespaces from child tags with `etree.QName(child).localname`. Stdlib alternative for
untrusted input: `defusedxml.ElementTree.iterparse` [third-party: defusedxml], which rejects
entity declarations, with the same clearing discipline (stdlib elements have no
`getprevious`, so clear the root's children instead). lxml's default entity behaviour changed
across 5.x releases — set the options explicitly rather than relying on defaults
(VERIFY: lxml release notes for your version).

### 5.7 pandas and Polars for bulk/analytical paths

```python
import pandas as pd                       # [third-party: pandas]
import polars as pl                       # [third-party: polars]

def csv_chunks(path: str) -> Iterator[pd.DataFrame]:
    yield from pd.read_csv(path, chunksize=50_000, dtype=str, keep_default_na=False,
                           encoding="utf-8-sig", usecols=["sku", "qty", "price"])

def csv_to_parquet(src: str, dst: str) -> None:
    (pl.scan_csv(src, infer_schema=False)  # all Utf8 (VERIFY: older Polars uses infer_schema_length=0)
       .select("sku", "qty", "price")
       .sink_parquet(dst))
```

`dtype=str` + `keep_default_na=False` stops pandas turning `"NA"` (Namibia, or a surname) into
NaN and `"00123"` into `123`. Locators: pandas chunk row index + header offset; Polars has
`with_row_index()` (VERIFY: older name `with_row_count`).

## 6. Production use cases

- **Payroll timesheet CSV from a desktop Excel export (cp1252, `;` delimiter, German locale).**
  Contract per tenant: `encoding="utf-8-sig"`, `fallback_encodings=("cp1252",)`,
  `delimiter=";"`. Decimal comma conversion happens in mapping, not parsing.
- **Hospital doctor roster (XLSX, title block on rows 1–3, merged cells).** Header detection
  scans 10 rows for `licence_number`, `specialty`; template requires text-formatted licence
  column so leading zeros survive; sheet chosen by name `Doctors`.
- **Bank statement ISO 20022 camt.053 XML (hundreds of MB).** `iterparse` on the namespaced
  `Ntry` element, cleared after each entry; amounts parsed with `Decimal`; XML syntax error at
  the end of the file fails the whole statement (it is a financial control document).
- **Product catalog feed (JSONL, 3M lines, nightly).** Line-level errors isolated; a bad line
  never blocks the catalog; error rate above the threshold fails the run.
- **Attendance device logs (fixed width, cp437).** Layout spec `(("badge", 0, 8), ("ts", 8, 22),
  ("door", 22, 26))`; trailing spaces stripped per field; unknown record types counted, not fatal.
- **Inventory snapshot from ERP (.xls, legacy).** Size capped at 20 MB; `xlrd` path; dates via
  `xldate_as_datetime`; long-term ask is `.xlsx` or CSV.

## 7. Advantages and disadvantages

| Approach | Advantages | Disadvantages |
|---|---|---|
| Stdlib `csv` generator | No dependency, exact line numbers, O(row) memory, string-preserving | Slower than columnar engines; manual typing |
| openpyxl read-only | Streams large sheets, typed values | Slow per cell (pure Python); cached formula values only |
| pandas chunks | Vectorised transforms, rich IO | Float/NaN coercion traps; row context loss; heavy dependency |
| Polars lazy | Fast, multi-threaded, streaming sinks | API churn across versions; less natural for per-row errors |
| JSON `json.load` | Simple, exact Decimal | Whole document in memory |
| JSONL | Streamable, per-line recovery | Producer must support it |
| lxml iterparse | Fast, streaming, XSD support | Native dependency; must harden + clear manually |

## 8. Security and performance considerations

**Security** (summary — full treatment in [data-processing-security.md](data-processing-security.md)):
- Detect type from magic bytes; reject on mismatch with the allowed set per import.
- XML: no entity resolution, no DTD loading, no network, no `huge_tree`; prefer defusedxml for
  stdlib parsers. XLSX is ZIP+XML: openpyxl uses defusedxml when installed — install it.
- Cap file size before parsing, cap record count and field size (`csv.field_size_limit`), cap
  JSONL line length, cap XLSX uncompressed size (ZIP bomb).
- Never echo raw cell values into HTML unescaped; formula-injection neutralisation applies on
  *export* of these values.
- Redact sensitive columns before storing raw payloads in error reports.

**Performance** (deeper in [data-processing-performance.md](data-processing-performance.md)):
- Generators end-to-end; never `list(reader)`.
- Stdlib `csv` handles roughly hundreds of thousands of rows/second on typical hardware;
  openpyxl is often 10–50x slower per cell (VERIFY: benchmark on your data). XLSX is usually
  the bottleneck — offer CSV for very large imports.
- `TextIOWrapper` over a remote storage stream: wrap in `io.BufferedReader` if the backend
  issues small range requests (VERIFY: django-storages buffering behaviour).
- XML without clearing grows linearly with file size — the most common OOM in XML imports.

## 9. Common mistakes and anti-patterns

- Opening CSV without `newline=""` → quoted multi-line fields split, wrong field counts → always `newline=""`.
- Decoding with `utf-8` instead of `utf-8-sig` → first header is `﻿email`, "missing column email" → use `utf-8-sig`.
- `errors="replace"`/`"ignore"` → silent data corruption (names with `�`) → strict decode, explicit fallback list.
- Trusting the file extension → XLS bytes named `.csv` parsed as text garbage → magic-byte detection.
- `enumerate(reader)` as the locator → line numbers off when fields contain newlines → `reader.line_num`.
- `load_workbook()` without `read_only=True` on large files → GBs of RAM → read-only + `wb.close()`.
- `data_only=True` on library-generated XLSX → all formulas `None` → document that files must be saved by Excel, or compute formulas yourself.
- pandas default dtypes → leading zeros dropped, `"NA"`/`"null"` become NaN, money as float → `dtype=str, keep_default_na=False`.
- `json.load` on a multi-GB array → OOM → JSONL or ijson.
- `iterparse` without `elem.clear()` + sibling deletion → memory grows with file → clear discipline.
- Mixing parsing and validation → parser cannot be reused, errors lack codes → parser yields raw records only.

## 10. Troubleshooting and validation

| Symptom | Likely cause | Check / fix |
|---|---|---|
| `Missing columns: email` but header looks right | BOM or non-breaking space in header | Decode `utf-8-sig`; NFKC-normalise headers |
| `Ã©` instead of `é` | UTF-8 bytes decoded as cp1252 | Remove cp1252 fallback for this source; re-decode as UTF-8 |
| `UnicodeDecodeError ... byte 0xe9` | cp1252 file under UTF-8 contract | Ask for CSV UTF-8 or add declared fallback |
| `field larger than field limit` | Unterminated quote swallowing the file | Check `line_num`; find stray `"` |
| openpyxl `max_row` = 1 for a big sheet | Wrong dimension tag | `ws.reset_dimensions()` |
| All formula cells `None` | `data_only=True` on never-calculated file | Open in Excel and save, or avoid formulas |
| Worker memory grows steadily on XML | Elements not cleared | Add `clear()` + `del parent[0]` loop |
| IDs `1.23E+11` | Excel numeric cell / scientific notation in CSV | Require text column in template |

Validation checklist:
- [ ] Encoding contract documented per source; fallbacks recorded on the job.
- [ ] Format detected from bytes; allowed formats per import type.
- [ ] Header normalised; missing/duplicate columns fatal before row 1.
- [ ] Every yielded record has a locator users can act on.
- [ ] Format errors and row errors use distinct exception types and codes.
- [ ] Memory stays flat on a 10x-size test file (see [data-processing-testing.md](data-processing-testing.md)).
